# 작성 방식과 사례

분석일: 2026-09-14. 사용자가 최근 작성 문서로 지정한 5개 문서에 대한 관찰이다. 별도 확정 지시가 없는 항목은 이 사례들에서 도출한 기본 작성 경향이며, 사용자 수정에 따라 갱신한다.

## 공통 경향

1. 목적을 먼저 설명하고 구현 가능한 규칙으로 좁힌다. 기능 자체뿐 아니라 유저가 무엇을 판단하거나 경험할 수 있는지 제시한다.
2. 간결한 개조식 문장과 단계적 들여쓰기를 사용한다. “표시”, “처리”, “추가”, “해금”, “재생”, “필요”처럼 동작과 상태 중심의 표현이 많다.
3. 대항목은 `1. 개요`, 하위 항목은 `2-1. ...` 같은 번호 구조다. 제목의 실제 크기는 문서별로 달라 고정하지 않는다.
4. 기존 규칙 재사용을 명시해 변경 범위를 줄인다. 필요한 예외와 공통 적용 범위를 바로 이어 설명한다.
5. 표는 비교, 상태 정의, 데이터 스키마, 키와 문구의 대응에 사용한다. 서술 전체를 무리하게 표로 바꾸지 않는다.
6. 이미지 위의 박스·화살표·번호와 본문을 연결한다. UI 문서는 화면 전체와 영역을 강조한 버전을 함께 제시하는 사례가 있다.
7. 핵심 정의와 예외는 콜아웃, 중요한 항목은 굵기·색상으로 강조한다. Markdown 전달 시 같은 의미가 제목·굵기·인용으로 유지되게 한다.
8. 스트링 키와 NPC 코드 등 실무 식별자를 설명 곁에 기록하고, 관련 상세 문서는 링크로 연결한다.
9. 기획 의도와 협업 확인 항목이 함께 존재한다. “희망”, “논의 필요”, “확인 필요”, “추가 예정”은 확정 사양으로 변환하지 않는다.

## 문서 유형별 구성 예시

### 기존 콘텐츠 확장 — 신규 특별조달 존 기획서 [택배 털이]

출처: https://app.notion.com/p/3c808a0561328030bd9fcdaaf6df7969

실제 흐름: 개요 → 처리 → 전투 → 리소스 리스트 → 관련 스트링 키 → 기타 추가 작업.

- 개요에서 신규 존의 이름, 획득 재화의 사용 목적, 기존 특별 조달 규칙 재사용을 명시한다.
- 처리에서 신규 Zone Type을 표로 제시하고, 순차 해금·별 조건·소탕 해금을 구체화한다.
- 전투는 콘셉트 이미지와 NPC 코드·링크로 구체화한다.
- 리소스는 UI와 인게임으로 구분하고 이미지 갱신과 신규 이미지를 구별한다. BGM은 확인 필요 상태다.
- 스트링의 가변 인자 `{0}`와 경로를 유지한다. 튜토리얼·가이드 변경 같은 연관 작업도 마지막에 남긴다.

### 시스템 변경 — 컨텐츠 시작, 종료 시간 조정에 따른 처리

출처: https://app.notion.com/p/3c308a05613280e5bd26db7ed4ab3799

실제 흐름: 개요(현황·문제 사항·제안 사항·적용 범위) → 처리(시작·종료·추가 고려 사항) → 초기화 시간 정책 참고 자료.

- 문제를 유저 피로와 연결한다. 기존 `Schedule_Data.open_date / end_date` 활용을 명시한다.
- 활동 UI를 계속 열어둔 상태의 시작 처리는 두 안을 병기한다. 둘 중 하나를 임의 확정하지 않는다.
- 종료 처리는 입장 버튼 터치, 콘텐츠 내부, 전투 중, 백그라운드 복귀로 나눠 기술한다.
- 팝업 확인 후 이동, 전투 결과 반영 여부, 입장 재화 처리, 로비 이동 후 보상까지 연결한다.
- 타 게임 시간 표는 참고 자료이며 해당 프로젝트의 시간 정책으로 복사하지 않는다.

### 신규 콘텐츠 — 이벤트 보스전

출처: https://app.notion.com/p/39e08a05613280a3a448ece01b193edb

실제 흐름: 개요(목적·방향성) → 보스전 규칙 → 컨텐츠 진행 및 요소 → 데이터 구조.

- 기존 이벤트 작전과 목적·전투 대상·예상 플레이를 비교한다.
- 콘텐츠 진입 → 최초 다이얼로그 → 입장 화면 → 편성 → 전투 → 종료 다이얼로그 → 결과 → 이벤트 종료 후의 흐름으로 설명한다.
- 각 화면의 표시 정보, 버튼 동작, 갱신 시점, 내 기록 강조를 적는다.
- 반복 도전의 성격과 입장 재화 부재, 플레이 횟수 업적의 의도를 연결한다.
- 신규 ENUM과 스테이지 테이블은 이름·타입·의미로 정리한다.
- Top 100 표시는 가능 여부 확인 항목이고 보상은 논의 필요다. 원문의 랭킹 경계 표현과 NOW SCORE/BEST SCORE 동률 처리는 새 문서에서 요구사항이 되면 의미를 확인한다.
- 중복된 `3-7` 번호는 문서 편집 흔적이며 템플릿 규칙이 아니다.

### UI 상세 — 전투 결과 UI - 데미지 그래프

출처: https://app.notion.com/p/UI-33408a0561328049903bd56661ee9968

실제 흐름: 개요 → UI 구성 정보(UI 플로우·팝업 UI 정보) → 요청 리소스.

- 기존 아레나 화면과 타 게임 레퍼런스를 보여주고, 파티 기여도와 실패 원인 분석이라는 사용 목적을 설명한다.
- 적용 제외 범위(아레나)를 콜아웃으로 명시한다.
- 결과 화면의 신규 버튼과 팝업을 화살표로 연결한다.
- 팝업의 1~4번 영역과 타이틀·그래프/통계·캐릭터 아이콘·통계 카테고리를 대응시킨다.
- 최댓값을 기준으로 한 상대 그래프 길이 규칙을 명시한다. 모든 값이 0일 때의 규칙은 이 문서에서 확인하지 못했으므로 임의로 기존 사양화하지 않는다.
- 아이콘 요청에는 식별자·내용·용도·경로가 있다.

### UI 상세 — 전투 결과 UI - 타임 라인

출처: https://app.notion.com/p/UI-33c08a05613280858eb1fdadc372c44e

실제 흐름: 개요(용도·정의) → UI 구성 정보(UI 플로우·팝업 UI 정보).

- “파티가 의도대로 싸웠는지”를 핵심 정의로 제시하고, 유저가 확인하려는 질문으로 분석 목적을 구체화한다.
- 웨이브 버튼의 선택됨·선택 가능·선택 불가능 상태를 표로 정리한다.
- 타임 스탬프는 파티 순번(사거리 순), 스킬 분류 값, 아이콘 데이터 참조까지 연결한다.
- 버스트는 시각적으로 강조하며, 스킬 아이콘 터치 시 툴팁을 제공한다. 툴팁 상세는 추가 예정으로 남아 있다.
- 시간축은 1초 단위, 웨이브별 첫 스킬 사용 시점을 기준으로 설명한다.

## 새 문서에 적용할 때

사용자 입력에서 확인된 목적·범위·규칙으로 초안을 구성한다. 문서 유형과 무관한 장이나 불필요한 관리 표는 추가하지 않는다. 새로 제안한 보완점은 원래 요구와 구분한다. 필요한 상태 전이·경계값·예외가 빠졌다면 미정 항목으로 남기거나 작업을 좌우하는 정보만 질문한다.
