# HTML 문서 작성 규칙

## 1. 기준

HTML 기획 문서는 이 파일에 정리된 시각 양식과 구성 요소를 기준으로 작성한다. 원형 참고 자료명은 `Active_Skill_Group_Structure_Proposal.html`이며, 해당 파일이 없는 PC에서도 아래 명세를 적용한다.

- 문체와 정보 전개는 [공통 문서 작성 규칙](writing-rules.md)를 따른다.
- 이 파일은 HTML 출력 형식, 레이아웃, CSS, 시각적 표현만 정의한다.
- 결과물은 별도 빌드 없이 브라우저에서 바로 열 수 있는 단일 HTML 파일로 만든다.

## 2. 기본 파일 구성

- `<!DOCTYPE html>`을 선언한다.
- `<html lang="ko">`를 사용한다.
- `<meta charset="UTF-8">`을 포함한다.
- `<meta name="viewport" content="width=device-width, initial-scale=1.0">`을 포함한다.
- CSS는 `<head>` 안의 `<style>`에 포함한다.
- 외부 프레임워크와 외부 리소스에 의존하지 않는다.
- 문서 구조는 `<main>`, `<header>`, `<article>`, `<section>`, `<footer>`를 기본으로 한다.
- 결과물은 Microsoft Edge에서 로컬 파일로 바로 열 수 있어야 한다.
- Edge에서 별도 서버 실행, 확장 프로그램 설치 또는 빌드 과정 없이 정상 표시되어야 한다.
- 특정 브라우저의 비표준 기능에 의존하지 않고 현재 Microsoft Edge가 지원하는 표준 HTML과 CSS를 사용한다.

### 2.1 전달 방식

- HTML 문서 완성 후 사용자가 선택하여 열 수 있는 `.html` 파일 링크를 제공한다.
- 링크의 대상은 실제 로컬 파일의 절대 경로로 지정한다.
- HTML 문서를 전달할 때마다 문서가 저장된 폴더를 파일 탐색기에서 열 수 있는 폴더 링크도 함께 제공한다.
- 폴더 링크는 최종 응답에서 `문서가 있는 폴더 열기`처럼 용도를 명확히 표시한다.
- Windows 경로가 링크에서 중간에 잘리지 않도록 폴더 링크 대상에는 역슬래시(`\`) 대신 슬래시(`/`)를 사용한 절대 경로를 적용한다.
- 폴더 경로 링크는 꺾쇠괄호로 감싼 Markdown 대상 형식을 사용한다. 예: `[문서가 있는 폴더 열기](<C:/Users/User/Documents/>)`
- 폴더 링크 바로 아래에 열어야 할 정확한 HTML 파일명을 별도로 적는다.
- 사용자가 HTML 문서를 받거나 열기를 요청하면 Microsoft Edge에서 열 수 있도록 제공한다.
- 실행 권한과 환경이 허용되면 완성된 파일을 Microsoft Edge에서 직접 연다.
- 직접 열 수 없는 경우에도 Edge에서 열 수 있는 파일 링크와 정확한 로컬 경로를 함께 제공한다.
- 최종 안내에서 소스 코드만 전달하지 않고 완성된 `.html` 파일을 우선 제공한다.

## 3. 기준 레이아웃

### 3.1 페이지

- 전체 배경은 옅은 청회색 `#f3f6fa`를 사용한다.
- 문서 본문은 최대 너비 `1080px`의 흰색 카드로 구성한다.
- 기본 너비는 `min(1080px, calc(100% - 40px))`로 한다.
- 바깥 여백은 상단 `40px`, 하단 `80px`를 기준으로 한다.
- 카드에는 `18px` 둥근 모서리, 얇은 테두리, 약한 그림자를 적용한다.
- 카드 밖으로 요소가 넘치지 않도록 `overflow: hidden`을 적용한다.

### 3.2 헤더

- 헤더는 남색에서 파란색으로 이어지는 그라데이션을 사용한다.
  - 시작색: `#17243a`
  - 종료색: `#234d88`
- 헤더 여백은 `54px 64px 46px`을 기준으로 한다.
- 상단에 영문 또는 짧은 분류명용 eyebrow를 둔다.
- 제목은 흰색, `clamp(28px, 4vw, 42px)`, 줄간격 `1.25`를 기준으로 한다.
- 제목 아래에 문서 목적을 한 문단으로 요약한다.
- 하단 메타 영역에는 문서 버전, 작성일, 범위 등을 배치할 수 있다.
- 제목이 길면 의미 단위로 `<br>`을 사용해 두 줄로 나눌 수 있다.

### 3.3 본문과 섹션

- 본문 `<article>`은 좌우 `64px`, 하단 `64px` 여백을 사용한다.
- 각 `<section>`은 위아래 `42px` 여백과 하단 구분선을 사용한다.
- 마지막 섹션의 구분선은 제거한다.
- 섹션 제목은 번호 배지와 제목을 나란히 배치한다.
- 번호 배지는 파란색 배경의 `36px × 36px`, `10px` 둥근 모서리를 사용한다.
- `<h2>`는 남색, `25px`; `<h3>`는 남색, `18px`을 기준으로 한다.

## 5. 타이포그래피

- 글꼴은 `"Pretendard", "Noto Sans KR", "Malgun Gothic", sans-serif` 순서로 사용한다.
- 본문 크기는 `15px`, 줄간격은 `1.72`를 기준으로 한다.
- 한국어 문장이 단어 중간에서 끊기지 않도록 `word-break: keep-all`을 사용한다.
- 기본 본문색은 `--ink`, 보조 정보는 `--muted`를 사용한다.
- 데이터 키와 코드 값은 `<code>`로 표시하고 Consolas 계열 고정폭 글꼴과 옅은 파란 배경을 적용한다.

## 6. 문서 구성 요소

내용에 필요한 구성 요소만 선택한다.

### 6.1 핵심 요약 `.summary`

- 헤더 다음, 첫 섹션 전에 배치한다.
- 핵심 제안이나 결론을 한두 문장으로 압축한다.
- 옅은 파란 배경, 파란 왼쪽 테두리, 굵은 글씨를 사용한다.
- 문서 하단의 최종 요약에도 재사용할 수 있다.

### 6.2 카드 `.card-grid`, `.card`

- 서로 다른 3개 안팎의 개념, 역할, 현재 한계를 병렬 비교할 때 사용한다.
- 데스크톱에서는 3열, 모바일에서는 1열로 배치한다.
- 카드 첫 줄은 `<strong>`으로 제목을 표시한다.
- 단순 목록을 장식하기 위해 사용하지 않는다.

### 6.3 흐름도 `.flow`, `.flow-box`, `.arrow`

- 3단계 관계나 데이터 흐름처럼 선형 관계가 중요한 경우에 사용한다.
- 기본 구조는 `상자 → 강조 상자 → 상자`이다.
- 중앙 핵심 상자는 옅은 초록색 `.group` 스타일로 강조할 수 있다.
- 모바일에서는 세로 흐름으로 전환하고 화살표를 회전한다.

### 6.4 표

- 컬럼 의미, 전후 비교, 단계별 값, 검증 항목을 표현할 때 사용한다.
- 전체 너비, 둥근 외곽선, 옅은 청회색 머리글을 사용한다.
- 셀은 위쪽 정렬하며, 테두리가 중복되지 않게 마지막 행·열을 처리한다.
- 모바일에서 가로 스크롤을 허용한다.
- 긴 서술을 무리하게 표에 넣지 않는다.

### 6.5 규칙 블록 `.rule`

- 독립적으로 읽어야 하는 핵심 규칙을 한 항목씩 표시한다.
- `규칙 n — 제목` 또는 `포함`, `별도 검토`처럼 짧은 제목을 먼저 둔다.
- 일반 규칙은 흰색, 제외 범위는 `.out-of-scope`의 옅은 빨간색으로 표현한다.

### 6.6 상태 박스 `.note`, `.warning`, `.out-of-scope`

- `.note`: 예시, 정상 동작, 확정 보충 설명에 사용한다.
- `.warning`: 문제, 주의, 미확정, 현재 한계에 사용한다.
- `.out-of-scope`: 제외 범위와 별도 검토 대상에 사용한다.
- 색상만으로 의미를 전달하지 말고 텍스트 제목이나 문장으로 상태를 함께 표시한다.

### 6.7 이미지 제안

- 실제 이미지가 없으면 `[이미지 추가 제안]`을 사용한다.
- HTML에서는 `.rule` 또는 `.note` 형태의 블록으로 표현할 수 있다.
- 캡처 화면, 강조 영역, 설명 목적을 함께 적는다.

## 7. 반응형 규칙

화면 너비 `780px` 이하에서 다음을 적용한다.

- 문서 카드 너비를 `min(100% - 20px, 1080px)`로 줄인다.
- 상단 여백을 `10px`로 줄인다.
- 헤더와 본문의 좌우 여백을 `24px`로 줄인다.
- 카드 그리드는 1열로 변경한다.
- 흐름도는 세로 1열로 변경한다.
- 흐름도 화살표는 `90deg` 회전한다.
- 넓은 표는 블록 요소로 만들고 가로 스크롤을 허용한다.

## 8. 인쇄 규칙

- `@media print`를 포함한다.
- 인쇄 시 배경은 흰색으로 변경한다.
- 문서 카드는 전체 너비로 만들고 바깥 여백, 테두리, 그림자를 제거한다.
- 가능한 경우 섹션이 페이지 중간에서 나뉘지 않도록 `break-inside: avoid`를 적용한다.
- 색상이 제거되어도 제목 계층과 표 구조를 이해할 수 있어야 한다.

## 9. 기준 HTML 골격

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>문서 제목</title>
  <style>
    /* 이 규칙의 기준 색상과 레이아웃 적용 */
  </style>
</head>
<body>
  <main>
    <header>
      <div class="eyebrow">Document Category</div>
      <h1>문서 제목</h1>
      <p>문서 목적을 설명하는 한 문단</p>
      <div class="meta">
        <span>문서 버전: v0.1</span>
        <span>작성일: YYYY-MM-DD</span>
        <span>범위: 기획 범위</span>
      </div>
    </header>
    <article>
      <div class="summary">핵심 제안 또는 결론</div>
      <section>
        <h2><span class="number">1</span>섹션 제목</h2>
        <p>본문</p>
      </section>
    </article>
    <footer>문서 범위 또는 참고 문구</footer>
  </main>
</body>
</html>
```

## 10. HTML 검수 기준

- 첨부 기준 문서와 동일한 남색 헤더 및 흰색 카드 구조인가?
- 헤더에 제목, 목적 문장, 필요한 메타 정보가 있는가?
- 핵심 요약이 첫 섹션 전에 배치되었는가?
- 섹션 번호 배지와 제목 계층이 일관적인가?
- 표, 카드, 흐름도, 상태 박스가 내용상 필요할 때만 사용되었는가?
- 모바일에서 카드, 흐름, 표를 읽을 수 있는가?
- 인쇄 또는 PDF 저장 시 내용이 잘리지 않는가?
- 외부 리소스 없이 단일 파일로 열리는가?
- 한국어와 `<title>`이 UTF-8로 정상 표시되는가?
- Microsoft Edge에서 로컬 파일로 직접 열리는가?
- 최종 응답에 Edge에서 열 수 있는 실제 `.html` 파일 링크가 포함되었는가?
- 최종 응답에 문서가 저장된 폴더를 여는 탐색기 링크와 정확한 HTML 파일명이 포함되었는가?
